# Grok Build closure goal 5

Work directly in this ForeScene repository and implement the remaining adversarially verified gaps. This is an implementation goal, not a report-only audit. Use Grok 4.6 with high reasoning effort. Independent verification now passes the full unit suite, lint, production build, CLI help, diff check, and all 22 Chromium smoke tests. The following concrete issues remain in the current source; close them with focused behavioral tests and proportional documentation:

1. Make normal artifact download genuinely bounded on the Node side. `scripts/agent/artifactIo.ts` reads bounded `Blob.slice()` windows in the page, but still pushes every decoded chunk into `Buffer[]` and calls `Buffer.concat(chunks)` before writing. Replace that accumulation with a safe sequential file sink/stream (respecting backpressure and cleanup on failure) so the normal path does not retain a second full artifact in memory. Keep the explicit 8 MiB whole-file fallback and its refusal semantics. Add a test that proves chunks are written incrementally and the sink is closed on success/failure.

2. Surface honest transfer telemetry. `saveAgentArtifactToFile` returns `transferMode` but `runPackage` and `runVideo` discard it and print only `savedPath`; the provenance/status output does not identify whether the download used Blob slices or the fallback. Include bounded transfer metadata (mode, page materialization mode, byte length/chunk count where available) in the CLI result and/or run manifest for every artifact download path, without pretending browser-blob is a streamed file. Update docs and tests.

3. Enforce revision-bound validation evidence. `recordRunValidation`/`composeAgentValidationEvidence` currently accepts an arbitrary `revisionId` even when it differs from the active project revision; the existing test records `rev_fail` while the active revision is `rev_test`. Decide and implement a clear contract: either reject/diagnose mismatched evidence or record an explicit mismatch/stale gate and ensure it cannot be reported as a valid revision-bound summary. Preserve historical evidence only if it is clearly labeled as not current. Add tests for matching, mismatching, and absent revision IDs, and ensure CLI verify still records the current revision without extra renders.

4. Do not silently classify ordinary visible content as environment-only merely because subject inference found no candidates. `resolveVisualPreflightSubjectPolicy` currently makes any shot with zero candidate subject IDs environment-only. A visible imported model/monster/prop can therefore receive N/A subject checks and a perfect score. Preserve explicit `environmentOnly` input and explicit shot metadata/shotKind, but add a bounded ordinary-shot warning/failure policy for visible renderable content whose subject inference is empty; add regressions for a visible imported model/prop and for an explicitly environment-only set. Keep legitimate set-only shots supported through explicit intent.

5. Re-audit package inclusion so a caller cannot turn a planned path or fabricated string into proof that a ZIP contains bytes. The current test passes paths extracted from a real ZIP, but `inspectAssetPoseContract({ packageManifestPaths })` accepts any iterable and `isProducedPackageManifestPath` only filters shape. Add or use a package-manifest extraction/verification helper tied to the actual produced ZIP/artifact, keep `not_verified` when proof is absent, and test a fabricated matching path, an omitted ZIP entry, and a real exported ZIP. Do not reintroduce artifact-id or digest-as-path false positives.

6. Recheck cancellation and artifact lifecycle edge cases after these changes: repeated/terminal production cancellation must not create a false cancellation event; missing-handler/failed/cancelled jobs must settle in-flight artifacts and terminal timestamps consistently while authoritative results remain pinned. Add focused regressions only where the audit finds a real issue.
