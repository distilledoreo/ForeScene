# Grok Build closure goal 4

Work directly in this ForeScene repository and implement the remaining benchmark-remediation gaps. This is an implementation goal, not a report-only review. Use Grok 4.6 with high reasoning effort. Read the current source, tests, docs, and the prior closure-goal changes before editing. Preserve user-owned untracked artifacts, benchmark outputs, and the canonical/adapter skill files; use the official skill-sync workflow for any skill changes.

The previous remediation passes made the core package, recovery, cache, visual-preflight, artifact, and CLI paths substantially stronger. Independent verification currently passes the full unit suite, lint, production build, CLI help, diff check, and Chromium smoke tests. Do not undo those improvements. Close the following concrete gaps, adding focused behavioral tests and proportional documentation:

1. Wire provenance retry and cancellation telemetry to real paths. `recordProvenanceRetry` and `recordProvenanceCancellation` currently have no production callers, so provenance reports zero retries and `cancelled: false` even when agent/API/CLI operations retry, resume, or cancel. Connect the actual retry/resume/cancel paths (including CLI/session cancellation where applicable), define clear per-run/session reset semantics, and add tests proving `getStatus().provenance.retries` and `.cancelled` reflect real operations rather than only direct helper calls. Do not create false positives from unrelated process-wide state.

2. Make run provenance carry stable, revision-bound validation evidence. `verify` computes visual preflight, asset-pose, project-health, and validator results separately, while `AgentRunProvenance` currently contains none of those outcomes. Add a bounded, serializable quality/validation summary to provenance or the relevant command/run manifest, including the project revision it describes, so benchmark artifacts explain both execution and quality gates. Add tests for passing/failing summaries and ensure this does not trigger unbounded automatic renders or duplicate expensive work.

3. Give every CLI invocation a stable run identity. `withSession` currently publishes only command, harness, and profile. Add a generated per-invocation `runId` and propagate it through all CLI paths and provenance/manifests. Pass source commit/build identity when it is genuinely discoverable; never invent one. Add tests that exercise more than one CLI command and prove IDs are present, distinct per invocation, and preserved through the session.

4. Audit and, where the platform permits, repair artifact transfer so normal package/artifact downloads do not first materialize an unnecessary full-file `Uint8Array` before chunking. Prefer Blob/ReadableStream chunk transfer with bounded memory, keep the fallback explicit and size-capped, and expose honest transfer-mode telemetry. If a browser binding makes full Blob materialization unavoidable, document that limitation precisely, test the bounded behavior, and ensure the fallback is never silently selected.

5. Audit the artifact lifecycle. Job result handles should be pinned while in flight and authoritative result artifacts must remain pinned after completion, but `inFlight` must be cleared when the job/item settles and pin reasons must remain truthful. Implement the smallest safe lifecycle fix, cover success/failure/cancel paths, and retain the intentional default pinning of authoritative results.

6. Audit visual preflight when no subjects are inferred. A legitimate environment-only shot must remain supported, but an ordinary shot with no inferred subjects must not silently receive a perfect subject/coverage result. Add explicit environment-only semantics or a bounded warning/failure policy, make the distinction visible in the result, and add regressions for both environment-only and accidental-empty-subject shots.

7. Re-audit package inclusion against the actual export manifest/ZIP path. Keep the current `not_verified` state when a produced manifest is unavailable, and prove with an integration test that an asset is marked included only when the actual exported package manifest contains the planned path. No artifact ID may masquerade as a content hash or package path.

Work in the existing architecture; avoid broad rewrites. After implementation, run focused tests, then `npm.cmd run lint`, the full `npm.cmd run test`, `npm.cmd run build`, `npm.cmd run agent:help -- --json`, and `git diff --check`. Run `npm.cmd run test:e2e:smoke` if the environment permits. Inspect the final diff and report exact changed behavior, tests, and any limitation that remains. Leave the repository in a working state; do not commit or push.
