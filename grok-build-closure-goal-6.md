# Grok Build closure goal 6 — adversarial lifecycle and proof hardening

Use Grok 4.6 High to close the concrete gaps found after the previous remediation pass. Work in the current ForeScene repository. Do not commit or push. Preserve unrelated user-owned artifacts and existing benchmark outputs.

The previous passes are broadly implemented and the independent gates are green, but adversarial review found these remaining issues. Implement the smallest complete fix, update relevant docs, and add regression tests:

1. **ZIP proof must require actual archive bytes.** `src/engine/projectPackageInclusion.ts` currently accepts an arbitrary object shaped like `{ files: ... }` through `ZipLike`, then marks its paths as a verified manifest. A caller can fabricate a matching planned path and obtain `includedInPackage: true`. Remove or harden this bypass so only a real Blob/ArrayBuffer/Uint8Array archive parsed by JSZip (or an equivalently provenance-safe value) can create a verified proof. Add a test that a fabricated `{ files: { plannedPath: ... } }` object cannot prove inclusion. Keep the real `createProjectPackage` ZIP integration and omission cases passing.

2. **Generic job cancellation must be terminal-safe.** `src/engine/agent/jobQueue.ts` currently sets any job to `cancelled` even when it is already `completed`, `completed_with_warnings`, `failed`, or `cancelled`; the `alreadyTerminal` flag only suppresses telemetry. Make terminal cancel a no-op with a diagnostic, preserving the terminal status, finishedAt, artifacts, and provenance. Add tests for completed and failed jobs as well as active cancellation. Check `pause`/`resume`: `finishedAt` should describe terminal completion/failure/cancellation, not a paused intermediate state; clear or otherwise correctly manage it across resume and test the lifecycle.

3. **Visual preflight must not silently ignore visible content when another candidate exists.** The current no-candidate protection catches a lone imported monster/prop, but `resolveVisualPreflightSubjectPolicy` can still score an inferred human while ignoring a visible imported model/prop in the same ordinary shot. Define a clear policy: explicit `environmentOnly` remains the only N/A path; ordinary visible non-environment content that is not identified/scored must be reported as unresolved or otherwise fail/warn according to an explicit, documented set-dressing policy. Add a focused regression with a visible human candidate plus a visible imported model/prop and prove the output cannot be a perfect pass while the content is silently ignored. Preserve legitimate explicit environment-only shots and existing requested-subject behavior.

4. **Audit adjacent trust/lifecycle edges introduced by these fixes.** In particular, check that proof objects cannot be forged through alternate inputs, terminal job state is not mutated by repeated cancel, in-flight artifact pins are released exactly once, and CLI/browser transfer telemetry remains honest. If you find a concrete defect in those paths, close it with a regression test rather than merely documenting it.
